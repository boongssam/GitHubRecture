깃허브란?

제작하셨던 수많은 코드들,
잘 보관하고 계신가요?

GitHub = 코드 전용 저장 · 공유 · 공동작업 플랫폼

구글 드라이브, iCloud 같은 클라우드 저장소도 있지만, GitHub는 코드를 위해 만들어진 저장소입니다.

  • 저장 및 다운로드, 편집이 편리
  • 버전 관리 가능
  • 다른 수많은 개발자들의 오픈소스에 접근
  • 포트폴리오 등의 공유

기계가 일을 잘하게 돼 일상 업무를 자동화할수록 사람은 직접 수행할 기회를 점차 잃는다. 감시 책임은 사람에게 남지만, 바로 그 자동화 때문에 감시 능력은 퇴화한다.

필수 용어 — 알고는 있자!

Repository

프로젝트 폴더. 코드 파일과 그 변경 기록이 함께 들어 있는 저장소입니다. 줄여서 "레포"라고도 부릅니다.

Branch

수정을 위한 복사본. main 브랜치는 그대로 두고, 새 브랜치에서 작업한 뒤 검토(Review)를 거쳐 합칩니다(Merge).

Branch 흐름

내 컴퓨터 → 저장소까지 3단계

Working directory작업 중인 폴더
git add →
Staging area올릴 파일 장바구니
git commit →
Local repository버전(스냅샷) 저장
git push →
GitHub원격 저장소 (origin)

Git 명령어

git init

"git 저장소(폴더)를 만들어!"

현재 폴더를 Git이 관리하는 저장소로 만듭니다. 폴더 안에 숨김 폴더 .git이 생깁니다.

git add .

"현재 폴더에 있는 파일을 선택(스테이징)할게!"

.은 "현재 폴더 전체"라는 뜻입니다.

git commit -m "할말"

"'할말'로 버전 기록해줘!"

메시지에는 날짜나 수정 내용을 적어 두면 나중에 찾기 쉽습니다. 예: git commit -m "로그인 버튼 추가"

git branch -M main

"기본 브랜치 이름을 main으로 변경!"

Git의 기본 브랜치명은 master, GitHub의 기본 브랜치명은 main이라서 이름을 맞춰 줍니다.

git remote add origin GitHub주소

"origin이라는 이름으로 GitHub 레포지토리에 연결해줘!"

내 컴퓨터 🖥️ 🔗 GitHub. 한 번만 연결하면 됩니다.

git push -u origin main

"origin의 main에 업로드해줘!"

내 컴퓨터(main) → push → GitHub(origin/main). -u를 한 번 붙여 두면 다음부터는 git push만 입력해도 됩니다.

학교 컴퓨터에서 작업하다가, 우리 집에 왔을 때!

GitHub(origin/main) → pull 또는 clone → 집 컴퓨터(main)

git clone 레포지토리주소git pull origin main
언제?처음 내려받을 때이미 내려받은 뒤 업데이트할 때
결과저장소를 복제해 새 폴더를 만듭니다원격 변경 사항을 가져와 기존 폴더에 반영합니다

Fork: 레포지토리 복사

다른 사람의 GitHub 저장소 오른쪽 위 Fork 버튼을 누르면 내 GitHub 계정으로 사본이 만들어집니다.

비교ForkClone
복사 위치내 GitHub 계정내 컴퓨터
주요 목적기여 · 독립 작업로컬 작업
Push내 저장소라 push 쉬움원본 권한 없으면 push 불가
  • clone만: 내 소유 저장소가 아니므로 코드 수정 후 push 불가
  • clone → 새 레포 만들어 push: 가능하지만, 원본 코드에 pull request 보내기 어려움
  • fork → clone: 내 소유 사본 생성 → 코드 다운 → push 가능 ✅
💡 한 줄 요약: Fork는 GitHub에 복사, Clone은 컴퓨터에 복사
git switch -c feature

"feature라는 브랜치를 만들어 이동해!"

main은 안전하게 두고, 새 기능은 feature 브랜치에서 실험한 뒤 합칩니다.

git status

"작업 폴더와 스테이징 영역 상태를 보여줘!"

초록Changes to be committed
git add로 스테이징 영역(장바구니)에 정상적으로 올라간 파일
빨강Changes not staged for commit
Git이 추적하던 파일이지만, 수정 후 아직 git add를 하지 않은 파일
빨강Untracked files
새로 생겨서 Git이 한 번도 추적한 적 없는 파일

실습하기

웹페이지를 하나 만들어서
GitHub에 직접 업로드해 봅시다.

준비

명령어 (순서대로)

# 1. 로컬 저장소 초기화
git init
# 2. 파일 추가 및 첫 커밋
git add .
git commit -m "First commit"
# 3. 기본 브랜치 이름을 main으로 맞춤
git branch -M main
# 4. 방금 만든 GitHub 저장소 주소 등록
git remote add origin 주소
# 5. 원격 저장소로 첫 업로드
git push -u origin main

'주소' 자리에 복사한 저장소 주소를 붙여 넣으세요. 처음 push할 때 GitHub 로그인 창이 뜰 수 있습니다.
